# October 30–31, 2026: desktop chat, watch memory, actions and voice

[中文](UPDATE-20261031.md) | [English — full translation](UPDATE-20261031.en.md)

This repository maintains only the computer-side Screenmate application and its AstrBot bridge. General QQ, Bilibili and course capabilities remain in [astrbot-fish-capabilities](https://github.com/FigaroGao/astrbot-fish-capabilities). Install them separately. User runtime data, models and character assets are not uploaded to GitHub.

## Features in this update

- **Desktop chat:** Double-click the character or choose the tray's chat action to open a native input window, with Enter-to-send, retained drafts on failure and the latest reply. Chat remains available while watching is paused; typing never enables capture. Text uses the existing AstrBot persona, and desktop replies do not call the QQ transport. `--open-chat` opens input directly; `--open-panel` opens settings.
- **Isolated watch memory:** Starting/pausing defines a session with actual start, end and duration. Watching uses a separate conversation, inherits the original persona and retrieves memory within the original owner's scope; screen and application information are temporary request additions. About ninety seconds after ending, Xiaojing writes one dated summary with duration into the original long-term memory. Detailed notes stay in the separate session. Interrupted sessions close at their last heartbeat rather than counting offline time. Ambiguous external writes remain pending review instead of being blindly repeated.
- **Desktop information:** While watching is enabled, read foreground applications, visible top-level windows and minimized state. Do not enumerate all background processes or read input fields/window bodies. Information is unavailable when locked or paused.
- **Actions and placement:** Existing actions now have IDs and execution receipts; queued does not mean played. Support corners, edges, relative coordinates and placement next to an application window on the same monitor. Reject missing, cross-monitor or ambiguous windows rather than guessing. Center protection is enabled by default, routes cross-screen movement along the bottom and places bubbles near edges; it does not promise to avoid every game HUD. Dragging interrupts movement; pausing/hiding cancels old commands.
- **Visibility and flashing repair:** The character appears only while continuous watching is enabled; the tray and chat remain usable. Remove per-frame window-mask updates and use a stable transparent surface after rendering becomes ready. This does not establish that intermittent flashing is eliminated across every GPU, game and scaling combination.
- **Cached speech:** Thirty-six local PCM clips: thirty scene-specific automatic options and six generic companionship phrases restricted to manual audition. Silence is the default; skipping a text reply does not automatically trigger audio. Scene matching, cooldowns and expiry checks apply, and clips do not interrupt normal replies. Audio files stay in runtime rather than being uploaded.
- **Independent voice switch:** The local speech model starts disabled each launch. Enabling it loads asynchronously with off/loading/ready/stopping/failed states; speech is allowed only after actual readiness. Loading does not block text or watching. Cancel while loading; disabling or exiting requests the local resident service to exit and release CUDA without shutting down all WSL or unrelated programs. Preserve the existing FP16 voice; external services are not forcibly terminated.
- **Bubble/playback synchronization:** With voice ready, show the entire sentence when the corresponding PCM begins playing and retain it during playback. Disabled/loading speech or synthesis failure falls back to immediate text. This is not word-by-word subtitling or forced phoneme alignment. Cached clips can be manually auditioned without loading the model.
- **Five settings pages:** Watching and chat, actions and placement, voice and clip library, watch records, and connection/pairing. Show actual capture/cloud-vision/proactive-decision intervals, action receipts, memory-write state and final summaries. Actions default to preview-only. The voice library supports search, filters, audition and stop.
- **Browser extension:** Download the ZIP from connection settings; the native window saves it to the system Downloads folder. The user must still unzip it, enable browser developer mode and load the unpacked directory. It is not automatically installed. Only visible text from explicitly enabled pages is extracted.

## Installation and updating

Double-click `launch.cmd` and use the tray to open settings. Capture starts paused and voice starts off. Preserve private files such as `runtime/settings.private.json`. Install README dependencies and run the asset installer first; models, character resources and runtime databases are not distributed with source.

Bridge updates must include every Python file in its directory, including `watch_memory.py`; preserve configuration and then reload the bridge. Configure both the capability plugin and bridge with your own owner ID, session and model. USB uses `adb reverse tcp:17860 tcp:17860` over loopback only; do not expose public or LAN ports.

Maintenance tools now include `tools/tablet_api_helper.py` rather than depending on an external script on the maintainer's computer. Put adb in PATH or set `SCREENMATE_ADB` to its full path; `SCREENMATE_TABLET_API_HELPER` can override the helper file. `tools/connect_tablet.py` is for initial pairing and writes bridge settings. Existing installations should use `tools/update_tablet_bridge.py`, which backs up, updates and rolls back on failure. These helpers target the documented Termux layout and local AstrBot management interface; other layouts need adaptation. They are not universal installers. Pairing tokens and voice keys remain local.

## Validation and remaining uncertainty

All 66 local tests passed, covering isolated sessions, permissions, receipt states, desktop logic separate from video ffmpeg processing, voice-toggle cancellation/retry and simulated PCM start. Queued receipts were not treated as animation completion.

Reference-device checks confirmed real desktop input receiving a reply from the original persona/model; a final isolated-session summary stored in original memory with its receipt checked; native WebEngine action completion, arrival and manual interruption; the five-page UI, default previews and extension download. Actual FP16 loading took 216 seconds; disabling exited the process, and cancellation during loading also succeeded. The switch check played no test sound and enabled no capture.

Everyday observation is still needed for natural model selection of actions/clips, occasional flashing, perceived audio/bubble synchronization, full-screen games and physical monitors with mixed scaling. The extension was not installed automatically, and universal webpage compatibility has not been verified. A port, queue or local service accepting a request is not proof of complete end-to-end success.
